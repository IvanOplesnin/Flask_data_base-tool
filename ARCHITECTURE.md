# Архитектура backend-проекта

## Слои

| Каталог | Ответственность |
| --- | --- |
| `my_app/__init__.py` | Фабрика Flask-приложения и регистрация модулей. |
| `my_app/extensions.py` | Экземпляры Flask-SQLAlchemy и Flask-Migrate. |
| `my_app/models/` | ORM-модели и связи предметной области. |
| `my_app/forms/` | Валидация HTTP-форм Flask-WTF. |
| `my_app/web/` | Blueprint-контроллеры, преобразующие HTTP-запросы в вызовы сервисов. |
| `my_app/services/` | Независимая доменная логика: расчёты и операции предметной области. |
| `my_app/dashboards/` | Встраиваемые Dash-приложения. |
| `tests/` | Изолированные pytest-тесты без доступа к рабочей БД. |

## Запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
FLASK_CONFIG=production .venv/bin/flask --app DataTool:app run
```

Для тестов используется отдельная временная SQLite-база:

```bash
.venv/bin/pytest
```

## Доступы

После применения миграций создайте первого администратора интерактивной CLI-командой:

```bash
FLASK_SKIP_DASHBOARDS=1 .venv/bin/flask --app DataTool:app create-admin
```

Роли: `admin` управляет пользователями и удаляет записи, `writer` создаёт и изменяет данные, `reader` имеет доступ только к просмотру. Новых пользователей создаёт администратор на странице `/users`.

## Правила развития

- Контроллеры не содержат формулы и не обращаются к глобальному состоянию приложения.
- Новая доменная логика размещается в `services/` и покрывается unit-тестами.
- Изменения схемы вносятся только миграциями Alembic; рабочие SQLite-файлы не являются миграциями.
- Имена классов — в единственном числе, переменных — описательные `snake_case`; новые сокращения запрещены, кроме общепринятых (`id`, `db`, `url`).
